Contact-gradient accuracy

Does agreement across smaller timesteps and parameter changes make a simulated contact derivative reliable?

Gradient gate failedProvisional date: Feb 26, 2026
Paper PDF ↓Sources & citation
In this studyMethodResultsInterpretationLimitationsPaper & sources

Method

A self-contained rigid-body engine records trajectories, contact regimes, solver diagnostics, and numerical sensitivities. The proposed gate combines perturbation and timestep checks before accepting a derivative.

An independent analytic impact reference tests accuracy. An established event-time implementation provides a stronger baseline. Separate studies examine measured bouncing-ball trajectories, external CPU engines, and inverse identification costs.

Results

CheckResult
Proposed derivative gate18 of 19 smooth cases accepted; only 3 accepted derivatives meet the accuracy target
Event-time baselineAll 19 supported smooth cases pass; grazing input is refused
Measured-data transfer5.474 mm pooled root-mean-square vertical error across three untouched trials after one-trial calibration
Identification studyThe proposed controller fails the two-family cost target

Interpretation

Refinement agreement can converge on the wrong contact derivative. Use the event-time reference within its supported isolated-impact domain; treat the proposed gate as an empirical check, not a certificate.

Limitations

  • The engine is a CPU reference with a bounded collision and constraint set. General engine superiority is not established.
  • The event-time baseline does not cover resting contact, friction, joints, or simultaneous impacts.
  • The bouncing-ball transfer result is a separate forward-prediction check and does not validate the rejected gradient gate.
