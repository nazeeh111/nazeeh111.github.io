nstack

Find a reviewed specialist capability, inspect its exact source and prerequisites, then decide whether it belongs in the current task.

Scope of this case

This case verifies source-only discovery, not an installed runtime, live activation, rollback or another machine’s setup. A catalog route is not permission to install, and available source is not target-specific acceptance.

The problem

A list of agent skills does not explain when a capability applies, what it depends on or which licensed source will be installed. Discovery needs to stay separate from activation.

The mechanism

nstack keeps a reviewed capability registry with source revisions, selected paths, rights, activation conditions and task checks. Its search, show and route commands expose those decisions before installation. A component can contain several native skills; its catalog identifier is not the same as an installed skill name.

The observed result

The recorded search for web-ui-design returned component L010 with web-ui-design and mcp-builder. Show and route exposed the pinned upstream source, selected paths, rights and prerequisites. The absent temporary state directory stayed absent throughout this read-only session.

Foundations

Each selected capability keeps its upstream identity and license. In this recorded L010 case, the source is anthropics/skills at ca45fc496a3436251f191354091d557da31c15b5; only the eligible selected leaves are covered by the stated route.

Inspect the details

The actual command sequence is python3 nstack.py search web-ui-design --brief, followed by show L010 and route L010. The complete JSON outputs are retained as site assets, so readers can inspect the result rather than a mock terminal.

The selected route distinguishes Apache-2.0 frontend/MCP leaves from restricted artifact sources. Discovery, source preparation and actual target-runtime checks remain separate operations.
